Placement quality — importance retained vs optimal (single reference frame)

Labels carry class weights — city 100 · town 30 · road 8 · POI 1 — and the priority key is importance-first (how the label-placement literature scores quality: maximise total weight placed). Ceiling = near-optimal Maximum-Weight Independent Set (annealing) on full-resolution geometry — a fixed ground truth independent of the downscale slider. % of optimal scores only clean (non-overlapping) importance — a label rendered on top of another isn't validly placed and must not inflate the score (gross is shown greyed when it differs). clean by class shows where any gap comes from (dropping a city costs far more than a POI). Because the ceiling is fixed at full res, Downscale is an accuracy knob: finer (1) → higher % but slower; coarser → lower %. The overlaps column is the honesty check — placed labels sitting on top of another, measured at full resolution (not the variant's own grid, so a coarse downscale can't hide sub-cell collisions). iTowns' bitmap methods intentionally allow some (partial-occlusion packing); binary methods (grid, DOM, QGIS/PAL) stay near 0 at fine downscale but reveal real collisions as you coarsen. A high % is only real if overlaps stay low — read the two columns together. This snapshot is measured cold (one reference frame, render-history reset) so it reflects intrinsic placement quality; that is why bucket converges to sort as depth-buckets increase, rather than wandering with the frame-to-frame hysteresis feedback.
